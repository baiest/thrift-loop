# 016 — Plan: SEO meta, brand assets, README, and v1.0.0 release

## Approach

Three deliverables, sequenced so the site's `<head>` is verified by a test before anything else depends on it. Brand assets are generated by a script but committed as static files — Render's free-tier build must not download Chromium at build time.

Site URL is hardcoded (`https://thrift-loop.onrender.com`), not injected via env var: `.gitignore` excludes `.env.*` except `.env.example`, so a `.env.production` would never reach Render and every absolute URL (canonical, og:url, og:image) would silently ship empty.

## Key decisions

- Decision: commit generated PNGs instead of generating at build time — Rationale: Render's free build shouldn't need a Chromium download; assets are static and only change when re-run manually via `npm run assets:generate`.
- Decision: skip `favicon.ico` — Rationale: no ICO encoder is installed and adding one is an unjustified new dependency; SVG + PNG icons + manifest cover all modern browsers.
- Decision: `scripts/generate-brand-assets.ts` and `scripts/capture-screenshots.ts` live at repo root, not in `apps/web/` — Rationale: per-workspace coverage thresholds (85.01% in `apps/web/vitest.config.ts`) would otherwise count these scripts and drag the gate down; root-level scripts are outside every workspace's coverage scope.
- Decision: hardcode the Render URL in `index.html` — Rationale: env-var injection is defeated by `.gitignore`'s `.env.*` exclusion (see Approach).
- Decision: screenshots captured against the live Render URL, with a local-seeded fallback if the grid is empty — Rationale: matches user's explicit choice; free-tier cold start/empty data are handled defensively in the capture script rather than discovered at review time.

## Affected areas

- `apps/web/index.html` — full `<head>` rewrite
- `apps/web/src/seo/head-meta.test.ts` — new
- `apps/web/public/` — new static assets
- `apps/web/src/components/organisms/sidebar-nav.tsx` — verify/fix wordmark
- `scripts/generate-brand-assets.ts`, `scripts/capture-screenshots.ts` — new

- `README.md` — full rewrite

- GitHub repo settings and releases (via `gh` CLI)

## Risks

- Missing-asset silent 200: `apps/api/src/create-app.ts:36-46` serves `index.html` for any unmatched path (SPA fallback runs after `express.static`), so a typo'd asset path fails silently for OG scrapers. Mitigated by the asset-existence assertions in the test.
- Cold start (Render free tier sleeps): breaks both screenshot capture and live OG-scraper validation on first hit. Mitigated with a long timeout in the capture script and by warming the site before validating with Facebook/Twitter's card debuggers.
- Chromium must be installed (`npm run e2e:install`) before running either generator script — document in tasks.
- No persistent data on Render: live screenshots may show an empty grid. Capture script falls back to a local seeded build (`npm run e2e:server`) if so.
- Commit hook rejects AI-attribution content and enforces a strict 3-line, ≤50-char format — plain commits only.

## Test strategy

`apps/web/src/seo/head-meta.test.ts` is the only genuinely testable surface here (static markup + asset presence), written red-first against today's `index.html`, and turned green by the rewrite. It asserts:

- required meta tags are present and non-empty;
- every locally-referenced asset path exists under `apps/web/public/`;
- `site.webmanifest` parses and has the right fields;
- `robots.txt` exists with `User-agent: *`.

Not tested: README prose, generated image pixel content, GitHub-side metadata (all verified manually per the spec's acceptance criteria and this doc's verification steps). The script files at repo root have no test — they're one-off asset generators, not application logic, and sit outside every workspace's coverage scope by design.
